## 한 줄 결론

- **국내 병원 AI 근무표 시장의 지배적 접근**은 딥러닝이 아니라 **제약 기반 최적화(수리계획법/제약프로그래밍) + 규칙 엔진**이다. "AI"라는 마케팅 용어를 쓰지만 실제로는 STREAM이 `docs/SCHEDULER_SPEC.md`에서 이미 채택한 **CP-SAT류 접근과 근본적으로 같은 계열**이다.
- 학계에서는 **강화학습(RL) + GNN**, **ML과 CP의 하이브리드**가 최신 연구 흐름이지만, 아직 "Hard Constraint 보장"이 필요한 실무 시스템에서는 **정수계획법/CP-SAT가 압도적으로 우세**하다 (해 존재 시 제약 위반 없음을 보장할 수 있다는 점 때문).
- 실무에서 반복적으로 강조되는 성공 요인은 **알고리즘 자체보다 "제약조건 정제 + 사람의 수동 조정(override) 여지 + 개인 선호 반영률"**이며, 이는 STREAM의 `preferences`/`preferred` 필드 설계 방향과 일치한다.

## STREAM에 대한 시사점 (요약)

1. **CP-SAT(OR-Tools) 선택은 업계·학계 표준과 부합** — 국내 상용 서비스(듀티메이커, 듀티플래너 등)도 "제약조건 동시 계산" 방식을 표방하며, 학술적으로도 정수계획법/CP가 Nurse Rostering Problem(NRP)의 주류 해법이다.
2. **원티드 듀티(희망 근무) 반영률**을 핵심 품질 지표로 삼는 서비스가 많다 (듀티플래너 "평균 85% 이상 원티드 듀티 반영률"). STREAM도 Soft Constraint 가중치 튜닝 시 "희망 시간 반영률"을 정량 지표로 추적할 가치가 있다.
3. **완전 자동화보다 "AI 초안 + 관리자 수동 조정"** 구조가 병원 현장에서 선호된다 (Two-Stage Scheduling 논문, IH-NASS 등). STREAM 관리자 화면에도 확정 전 수동 조정 UI가 이미 필요 조건으로 논의되고 있다면 이 방향이 검증된 패턴이다.
4. **RL/GNN은 아직 시기상조**: 설명 가능성 부족, 학습 데이터 의존성, Hard Constraint 미보장 문제로 실서비스 적용 사례가 드물다. STREAM 규모(부서당 수십 명, 2주-1개월 단위)에서는 CP-SAT로 충분하며 RL 도입의 ROI가 낮다.
5. **효과 측정 방식**: 인하대병원은 "수기 대비 전후 비교"로 NOE(야간-비번-오후처럼 몸에 무리가 가는 패턴) 발생률, 연속 휴무 비율, 만족도를 정량화해 국제학술지(BMC Nursing)에 게재했다. STREAM도 배포 후 효과 검증 시 유사한 비교 지표 설계를 참고할 수 있다.
