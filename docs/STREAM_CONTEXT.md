# STREAM 서비스 관련 프로젝트 메모리 정리

## 1. 프로젝트 개요

STREAM은 서강대학교 SAINT 내부에 들어가는 **교내근로 통합 관리 시스템**이다. 학생의 교내근로 지원부터 직원의 모집공고 등록, 학생 선발, 근무표 생성, 대타 관리, 출결 및 운영 대시보드까지 하나의 흐름으로 통합하는 서비스다.

서비스명 STREAM은 이전에 **Sogang Total Recruitment & Efficient Administration Management**라는 의미로 제안되었다. 화면명 예시는 **“STREAM 교내근로 통합 관리 시스템”**으로 정리된 적이 있다.

---

## 2. 서비스 위치 / 전제

STREAM은 독립 웹서비스라기보다 **SAINT 내부 기능 또는 하위 모듈**로 들어가는 전제가 강하다.

### 학생용 SAINT

학생용 SAINT에는 다음과 같은 형태가 자연스럽다.

- SAINT 내 **STREAM 탭**
- 학생이 공고 검색, 지원, 지원상태 확인, 근무일정 확인, 대타 요청 등을 수행

### 직원용 SAINT

직원용 SAINT에는 다음과 같은 형태가 자연스럽다.

- 직원용 SAINT의 **STREAM 탭 하위**
- 직원이 공고 등록, 지원자 검토, 선발, 시간표 생성, 대타 승인, 출결/운영 현황 확인 등을 수행

---

## 3. 프로젝트 배경

현재 교내근로 운영은 여러 문제가 있다.

첫째, 교내근로 공고와 지원 채널이 통일되어 있지 않다. 에브리타임, 서담(서강대학교 구성원 온라인 커뮤니티), 청년광장 게시판(서강대학교 공식 온라인 커뮤니티) 등 여러 온라인 커뮤니티에 각 부서의 공지가 산재되어 올라온다. 학생 입장에서는 어떤 근로가 열렸는지 한눈에 보기 어렵고, 부서별 공고 방식이 달라 탐색 비용이 크다.

둘째, 직원 입장에서는 지원자 관리와 선발 과정이 표준화되어 있지 않다. 지원자 정보 확인, 적합도 판단, 선발 여부 관리가 엑셀이나 개별 문서에 분산될 수 있다.

셋째, 근무표 관리가 비효율적이다. 학생별 가능 시간, 부서별 제약조건, 근무 시간 배정 등을 수작업으로 조율해야 하며, 일정 변경 시 다시 조정해야 한다.

넷째, 대타 요청이 비공식 채널에서 처리된다. 카카오톡 등으로 대타를 구하는 방식은 기록이 남기 어렵고, 승인 주체와 책임 소재가 불분명해질 수 있다.

다섯째, 출결·근무시간·운영 현황이 통합적으로 관리되지 않는다. 부서별 운영 상태, 학생별 근무 이력, 대타 발생 현황 등을 한 화면에서 파악하기 어렵다.

## 4. 조사 기반

프로젝트 조사 데이터는 다음과 같이 정리되어 있으며, 추가 조사가 필요할 경우 더 조사할 계획이다.

- 학생 설문: 74명
- 직원 설문: 10개 부서
- 학생 인터뷰: 13명
- 직원 인터뷰: 1명

이 조사를 바탕으로 학생과 직원 양쪽의 문제를 함께 해결하는 방향으로 STREAM 기능이 설계되었다.

## 5. 핵심 사용자

### 학생

학생은 교내근로 공고를 탐색하고 지원하며, 자신의 지원 상태와 근무 일정을 확인하는 사용자다. 또한 근무가 어려운 경우 대타를 요청하거나, 가능한 대타 근무를 확인할 수 있다.

### 직원(관리자)

직원은 교내근로 공고를 등록하고, 지원자를 검토하고, 학생을 선발하며, 근무 시간표를 확정한다. 또한 대타 요청을 승인하거나 반려하고, 출결과 운영 현황을 관리한다.

## 6. 주요 기능

### 6.1 모집공고 관리

직원은 교내근로 모집공고를 등록, 수정, 조회할 수 있다. 기존 공고를 불러와 재사용하는 기능도 필요하다.

주요 화면은 다음과 같이 정리된 적이 있다.

- 모집공고 목록
- 모집공고 상세
- 모집공고 등록 / 수정
- 이전 공고 불러오기

추가적으로 AI를 활용해 공고 홍보글을 자동 생성하는 기능도 아이디어로 포함되어 있다.

### 6.2 학생 지원

학생은 여러 부서의 교내근로 공고를 통합 검색할 수 있다. 지원 시 학사 DB에 있는 기본 정보가 자동으로 채워지는 방향이 제안되었다.

학생 기능에는 다음이 포함된다.

- 교내근로 공고 통합 검색
- 공고 상세 확인
- 지원서 작성
- 학사 DB 기반 기본정보 자동 입력
- 지원 상태 대시보드 확인

### 6.3 학생 선발

직원은 지원자 목록을 확인하고, 각 지원자의 상세 정보를 검토한 뒤 선발·보류·탈락 처리할 수 있다.

이전 대화에서 학생 선발 화면은 다음과 같은 구조로 제안되었다.

- 왼쪽: 지원자 목록
- 오른쪽: 지원자 상세 정보 + 적합도 분석 패널
- 액션: 선발 / 보류 / 탈락

AI는 최종 판단자가 아니라 **보조 도구**로만 사용한다. 즉, AI가 적합도나 참고 근거를 제시하더라도 최종 선발 결정은 직원이 한다.

### 6.4 학생 관리

직원은 선발된 학생과 기존 근로 학생을 관리한다. 학생별 근무 상태, 배정 부서, 근무 가능 시간, 출결 정보 등을 확인할 수 있어야 한다.

### 6.5 근무 시간표 관리

근무 시간표 기능은 STREAM의 핵심 기능 중 하나다.

필요 기능은 다음과 같다.

- 학생별 가능 시간 수합
- 부서별 필요 인원 및 시간대 조건 반영
- 제약조건 기반 근무표 생성
- 주간 그리드 형태의 시간표 확인
- 여러 배정 시나리오 비교
- 최종 근무표 확정

중요한 설계 원칙은, **제약조건 기반 시간표 조율 기능은 AI Layer가 아니라 별도 Layer로 분리**해야 한다는 점이다. AI는 설명, 보조 판단, 추천에는 활용될 수 있지만, 실제 제약조건 계산 로직은 별도 모듈로 두는 방향이 적절하다.

### 6.6 대타 요청 관리

대타 요청 기능은 기존 카카오톡 중심의 비공식 대타 구하기 문제를 해결하기 위한 기능이다.

관리자 기능에는 다음 흐름이 포함된다.

- 대타 요청 목록 확인
- 요청 상세 확인
- 가능한 후보 검색
- 대타 후보 추천
- 승인 / 반려 처리

이전 관리자 IA에서는 대타 승인을 근무 시간표 내부 탭으로 둘 수 있다고 제안된 적이 있으나, 이후 admin shell 구조에서는 대타 요청을 별도 메뉴로 분리하는 방향도 정리되었다.

따라서 현재 기준으로는 **“대타 요청”을 독립 메뉴로 두는 안**이 더 명확하다.

### 6.7 출결 및 운영 대시보드

출결과 운영 현황을 통합적으로 확인하는 대시보드가 필요하다.

가능한 지표는 다음과 같다.

- 부서별 근로 학생 수
- 시간대별 배정 현황
- 출결 현황
- 대타 요청 발생 건수
- 미승인 요청
- 근무시간 누적 현황
- 운영상 리스크 또는 공백 시간대

## 9. AI 활용 방향

STREAM에서 AI는 자동 의사결정자가 아니라 **보조 도구**다.

가능한 AI 활용은 다음과 같다.

- 모집공고 홍보글 자동 생성
- 지원자 적합도 분석 보조
- 선발 근거 요약
- 근무표 배정 결과 설명
- 대타 후보 추천 사유 설명
- 운영 대시보드에서 이상 상황 요약
- 직원이 확인해야 할 항목 자동 요약

중요한 원칙은 다음과 같다.

- 최종 선발은 직원이 한다.
- 최종 근무표 확정은 직원이 한다.
- 대타 최종 승인은 직원이 한다.
- AI 판단 근거는 투명하게 제시되어야 한다.
- 시간표 생성의 핵심 제약조건 계산은 AI Layer가 아니라 별도 로직/알고리즘 Layer로 분리한다.

## 13. 기능 요구사항 요약

STREAM의 기능 요구사항은 크게 다음과 같이 묶을 수 있다.

### 학생 대상 기능

- 교내근로 공고 통합 검색

## 14. 설계 시 주의할 점

1. **STREAM은 SAINT 내부 서비스처럼 보여야 한다.**  
   독립적인 스타트업 서비스 느낌보다는 학교 행정 시스템의 하위 기능처럼 설계해야 한다.

2. **AI는 보조 역할로 제한한다.**  
   학생 선발, 근무표 확정, 대타 승인 같은 최종 결정권은 직원에게 있다.

3. **시간표 생성은 AI와 분리한다.**  
   제약조건 기반 시간표 조율은 별도 알고리즘 또는 백엔드 모듈로 설계해야 한다.

4. **대타 요청은 별도 메뉴로 두는 방향이 적절하다.**  
   기존에는 근무 시간표 내부 탭으로도 논의되었지만, 관리자 IA에서는 별도 메뉴로 분리하는 안이 더 명확하다.

5. **학생과 직원의 문제를 모두 해결해야 한다.**  
   단순히 학생용 공고 검색 서비스가 아니라, 직원의 행정 부담을 줄이는 운영 관리 시스템이어야 한다.

6. **조사 기반을 명확히 활용해야 한다.**  
   학생 설문 74명, 직원 설문 10개 부서, 학생 인터뷰 13명, 직원 인터뷰 1명을 근거로 문제정의와 기능 설계를 설명할 수 있다.

## 15. 한 줄 요약

STREAM은 서강대학교 SAINT 내부에 들어가는 교내근로 통합 관리 시스템으로, 공고 등록·지원·선발·근무표 생성·대타 승인·출결 및 운영 대시보드를 하나로 묶어 학생의 탐색 비용과 직원의 행정 부담을 동시에 줄이는 서비스다.
