# 리스크 & 향후 계획

각 문서에 흩어져 있는 "알려진 한계"를 한자리에 모으고, 무엇부터 손대야 하는지를 적습니다.
**추측이 아니라 코드·감사·실측에서 확인된 것만** 담고, 근거 문서를 함께 답니다.
마지막 갱신: 2026-09-01.

---

## 1. 운영에 들어가기 전 반드시 닫아야 하는 것

| 위험 | 현재 상태 | 근거 |
|---|---|---|
| **HTTPS 미적용** | 도메인 미발급으로 http만 서비스한다. Bearer 토큰과 비밀번호가 평문으로 오간다 | [AUTH_SPEC](AUTH_SPEC.md) 8절 |
| **서버 측 토큰 무효화 없음** | 로그아웃은 `sessionStorage`만 지우고, 발급된 JWT는 60분 만료까지 유효하다. 리프레시도 블랙리스트도 없다 | 〃 |
| **`SECRET_KEY` 기동 검증 없음** | 기본값이 `"change-this-secret-key"`이고, 운영 `.env` 주입을 빠뜨려도 앱이 그냥 뜬다 | 〃 |
| **정식 마이그레이션 도구 없음** | `schema_patches.py`가 `ADD COLUMN IF NOT EXISTS` + 멱등 UPDATE로 대신한다. 컬럼 추가·역채움까지는 되지만 **컬럼 삭제·타입 변경은 다루지 못한다** | [ERD](ERD.md) 8절, [ARCHITECTURE](ARCHITECTURE.md) |
| **개인정보를 외부 LLM에 보낸다는 사실 자체** | 비식별화로 식별자는 0건까지 줄였지만(실측), 특이사항·대타 사유 **문장 자체는 그대로 나간다** — 판단에 필요하기 때문 | [AI_SYSTEM](AI_SYSTEM.md) 1절 |

첫 세 건은 데모 환경 한정으로 감수 중인 항목입니다. 실사용자 데이터가 들어오는 순간
성격이 달라집니다.

## 2. 기능이 반쪽인 곳

### 서버는 있는데 화면이 없다

**#185 학생 자연어 특이사항이 대표적입니다.** 저장 테이블·프롬프트 섹션·AI 슬롯 제안·
담당자 조회 API까지 다 있는데 **학생이 문장을 넣을 입구가 없어**, 실제로는 시드로 넣은
값만 흐릅니다. 배치 검증(`GET /api/schedule/verify`)은 챗봇 툴로만 닿을 수 있고 화면
버튼이 없으며, 학생팀장 지정(`PATCH .../team-lead`)도 API로만 가능합니다.

`AdminDashboardPage.jsx`는 완성돼 있는데 **라우트가 없어 도달할 방법이 없습니다.**
수동 근무 등록·지원서 가능시간 연동은 `client.js` 바인딩만 있고 버튼이 없습니다.

→ 상세는 [IA_AND_SCREENS](IA_AND_SCREENS.md) 3절

### 계측은 되는데 변별력이 없다

**AI 검토(26케이스)와 챗봇(21케이스) 모두 만점입니다.** 하네스가 스스로 "계측기 포화"를
경고하도록 만들어 뒀는데, 검토에서만 세 번 그 경고가 떴습니다. 점수가 낮은 게 아니라
**만점이라 다음 변경의 효과를 잴 수 없는** 상태입니다 (#195).

대타 검사 하네스는 한술 더 떠, **프로덕션과 다른 프롬프트를 재고 있습니다** — 비식별화를
건너뛰어 실명 프롬프트로 측정합니다. `eval_review.py`가 2026-08-30에 고친 것과 같은
결함이고, 이 하네스가 한 번도 실행되지 않아 드러나지 않았습니다.

→ 상세는 [AI_SYSTEM](AI_SYSTEM.md) 3절

## 3. 알고리즘이 의도대로 동작하지 않는 구간

제약 감사에서 **"구현이 명세와 같다"와 "제약이 의도한 효과를 낸다"는 다르다**는 것이
드러났습니다. 감사 25개 제약 전부 명세와 일치하지만, 그중 하나는 특정 조건에서 아무 일도
하지 않습니다.

| 관찰 | 내용 | 영향 |
|---|---|---|
| **⑤ SC-FAIR-1 무효 구간** | 부서 학생 전원의 가용 슬롯이 주간 상한 이상이면 `Σ미달`이 배분과 무관한 상수가 되어, **어떻게 나눠도 페널티가 같다** | 총수요 < 총capacity인 부서(아텍·교육대학원 등)에서 공평 배분이 작동하지 않고, 실제 배분은 `contiguity`가 정해 **소수에게 몰아준다** |
| ① SC-CONT-1 다구간 병합 | 점심 휴관처럼 하루 개관이 끊기면 휴관을 사이에 둔 두 근무가 한 블록으로 계산된다 | 근무 블록이 정의된 부서는 완화됐으나, **`work_slots`가 없는 교육대학원은 전 요일 해당** |
| ② SC-MEAL-1 상수 페널티 | 식사 창이 수업만으로 찬 학생은 배정과 무관하게 위반이 잡힌다 | 최적화는 왜곡되지 않지만 담당자 리포트에 "배정 탓이 아닌" 위반이 뜬다 |
| ④ 토/일 시작 시험 | 명세가 월-금 시작만 정의하는데 코드는 임의로 판정한다 | 실데이터에 등장하면 규칙을 먼저 정해야 한다 |
| ⑥ 아텍 정책의 빈 설정 | `meal_missed: 20` 가중치는 있는데 `meal_windows`가 빈 목록, 밴드도 0개 | `SC-MEAL`·`SC-STAFF`가 아예 생성되지 않는데 **파일만 보면 켜져 있어 보인다** |

**⑤가 가장 큽니다** — 실측으로, 배정 분포가 `{0h:5, 3h:6, 6h:6, 12h:3}`에서
`{0h:8, 6h:9, 12h:3}`으로 달라졌는데 objective가 2484로 완전히 동일했습니다.
2주간 한 번도 배정받지 못하는 학생이 생기는 구조입니다.

→ 상세는 [SCHEDULER_CONSTRAINT_AUDIT](SCHEDULER_CONSTRAINT_AUDIT.md) 관찰 사항

## 4. 실서비스 연동 전제

지금은 없어서 **사람이 대신 넣고 있는** 것들입니다. 연동되면 화면과 규칙이 함께 바뀝니다.

| 항목 | 지금 | 연동 후 |
|---|---|---|
| SAINT 수강 시간표 | 학생이 `class_time`에 직접 입력 (REQ-SCHED-015) | 자동. 지금은 **HC-CLASS-1이 이 테이블을 참조하지 않고**, 학생이 가능 시간에서 수업을 스스로 빼는 데 의존한다 |
| SAINT 학적 정보 | 시드가 채운다 (학적상태·학년·지도교수 등 12개 컬럼) | 자동 |
| 부서 정책 | 내용은 `config/departments/*.json` 파일, DB에는 파일 키만 | 전면 DB화 |
| 계정 | 시드 스크립트로 생성 (회원가입·비밀번호 변경 API 없음) | 학교 계정 연동 |

## 5. 향후 계획

우선순위는 **"틀린 결과를 낼 수 있는 것 → 운영 안전 → 반쪽 기능 → 정리"** 순입니다.

### P0 — 결과의 정확성

1. **SC-FAIR-1 배분 축 수정** (3절 ⑤). 정보서비스팀까지 영향이 가므로 같은 조건에서
   전후 배정 분포와 objective를 함께 재야 합니다
2. **AI 계측기 변별력 회복** (#195) — 케이스를 어렵게 늘려야 다음 프롬프트 변경을 잴 수 있습니다
3. **대타 검사 하네스를 프로덕션 경로에 맞추기** — 지금 수치는 실명 프롬프트 기준이라 비교 불가

### P1 — 운영 안전

4. HTTPS 적용 (도메인 발급 후)
5. `SECRET_KEY` 기동 시 검증 — 기본값이면 뜨지 않게
6. 마이그레이션 도구 도입 (alembic)
7. `POST /api/schedule/review/clarifications`에 부서 스코프 검사 추가 — 다른 직원 전용
   경로와 기준이 다릅니다

### P2 — 반쪽 기능 마감

8. 학생 특이사항 입력 화면 (#185) — 백엔드가 다 있는데 입구만 없습니다
9. 배치 검증 버튼, 학생팀장 지정 화면
10. `AdminDashboardPage` 라우트 연결 또는 삭제 — 둘 중 하나로 정해야 합니다
11. AI 검토를 Hard/Soft Constraint 준수까지 확장 (#242)

### P3 — 정리

12. `response_model` 미선언 9건 (#78)
13. 로더 임시 처리 정리 (#52)
14. 컴포넌트 문서, 시나리오 비교 화면, TA 근무를 확정 근무표로 펼치기
