# 근무 시간표 생성 알고리즘 명세

---

## 이 문서를 읽는 법

이 문서는 STREAM의 핵심 기능인 **근무 시간표 자동 생성**(STREAM_CONTEXT 6.5)의 알고리즘 명세입니다. 어떤 입력을 받아 어떤 규칙으로 시간표를 만들어내는지를 정의하며, 백엔드 구현(`backend/app/scheduler/`)과 1:1로 대응됩니다.

- **제약조건 ID**: Hard Constraint는 `HC-분류-번호`, Soft Constraint는 `SC-분류-번호` 형식입니다. 코드 리뷰나 QA에서 "HC-TIME-2 위반" 식으로 참조합니다.
- 관련 문서: [API_SPEC.md](API_SPEC.md)의 근무표 API, [STREAM_CONTEXT.md](STREAM_CONTEXT.md) 6.5절

**설계 원칙**: 제약조건 기반 시간표 계산 로직은 **AI Layer가 아니라 별도 모듈**로 분리한다 (STREAM_CONTEXT 6.5). LLM은 제약조건의 수집·정제·설명에만 쓰고, 실제 배정 계산은 이 문서가 정의하는 결정적(deterministic) 알고리즘이 수행한다.

---

## 1. 문제 정의

### 1.1 무엇을 푸는 문제인가

여러 근로학생의 **근무 가능/희망 시간**과 부서의 **운영 제약**(개관 시간, 인원, 근로 시간 상한)을 입력받아, 다음을 만족하는 배정표를 찾는다.

- **Hard Constraint는 반드시 전부 만족** — 하나라도 어기는 배정은 답이 아님
- **Soft Constraint는 위반량 × 가중치의 총합을 최소화** — 다 만족할 수 없을 때 "덜 아픈 쪽"을 선택

이는 조합 최적화 분야에서 **직원 근무표 편성 문제(Employee Shift Scheduling / Nurse Rostering)** 로 잘 알려진 문제 유형이다.

### 1.2 알고리즘 선택: CP-SAT

| 후보 | 채택 여부 | 이유 |
|---|---|---|
| **CP-SAT** (Google OR-Tools) | ✅ 채택 | 해가 존재하면 Hard Constraint 충족을 **보장**. Soft Constraint를 가중 목적함수로 자연스럽게 표현. 부서 단위 규모(학생 수십 명 × 2주 × 30분 슬롯)에서 수 초-수십 초 내 풀이 |
| ILP (정수계획법) | ❌ | 가능하지만 논리 제약("연속 근무", "마감 후 아침 금지")의 선형화가 번거로움 |
| 유전 알고리즘 / Simulated Annealing | ❌ | Hard Constraint 충족을 **보장하지 못함** — "제약 만족이 필수"라는 요구와 충돌 |
| 그리디 + 수작업 조정 | ❌ | 현행 방식. 시간 상한 위반 리스크, 조율 비용 큼 |

### 1.3 결정 변수

```
x[s, d, t] ∈ {0, 1}
  s: 학생, d: 날짜, t: 슬롯(하루 내 30분 단위 시작 시각)
  1이면 "학생 s가 날짜 d의 슬롯 t에 근무"
```

- 슬롯 길이는 부서 정책 `slot_minutes`로 조정 가능 (기본 30분 — 페이 지급 최소 단위)
- **변수는 배정이 원천적으로 가능한 슬롯에만 생성**한다. 즉 "개관 시간 밖", "근무 가능 시간 밖", "수업 시간"에는 변수 자체가 없으므로 이 제약들은 위반이 불가능하다 (2.1의 도메인 인코딩 참고)

## 2. 입력 데이터

### 2.1 학생별 수합 데이터 (시간표 수합)

| 항목 | 형식 | 설명 |
|---|---|---|
| `funding_type` | `gyobi` \| `gukga` | 교비 / 국가 근로 구분 — 시간 상한과 휴강일 규칙이 다름. `student.funding_type` 컬럼에 동일한 값으로 저장 (DB 로더 연동 시 이 컬럼 사용) |
| `available` | 요일별 시간 구간 목록 | **근무 가능 시간** (학생이 체크) |
| `preferred` | 요일별 시간 구간 목록 | **근무 희망 시간** — 가능 시간과 분리 수합해 만족도 높은 배정 유도 |
| `class_times` | 요일별 시간 구간 목록 | 수업 시간표 (SAINT 연동 전제) |
| `date_schedule` | 날짜별 {available, preferred, classes} | **날짜 단위 수합** — 있으면 위의 요일 반복 대신 사용. 공휴일·시험 주차 예외를 자연스럽게 담을 수 있어 실서비스 저장 형식으로 권장 |
| `active_from` / `active_until` | 날짜 | 근무 시작일/종료일 — 기간 밖 배정 불가 (중도 합류·시즌별 근무 반영) |
| `exams` | (날짜, 시작, 끝) 목록 | 시험 일시 — 직전 배정 회피용 |
| `unavailable_dates` | 날짜 목록 | 특정일 근무 불가 (Hard) |
| `avoid_ranges` | (날짜, 시작, 끝) 목록 | 회피 희망 — 축제 당일 저녁 등 (Soft) |
| `preferences` | 개인 편의 옵션 | 아래 표 참고. **적용 유무는 학생별 선택** |

**실서비스 수합 경로 (DB)**: `POST /api/schedule/generate`는 위 데이터를 DB에서 읽는다 (`scheduler/service.py`의 `_load_students_from_db`). 부서 소속은 **해당 부서 공고에 `합격`한 지원서**로 판정한다.

| 도메인 필드 | DB 소스 |
|---|---|
| `date_schedule` | `available_time`(요일 반복) + `availability_exception`(날짜 예외)를 `loader/availability.py`가 날짜별 구간으로 전개 |
| `preferred` 판정 | `available_time.preference`가 **3(상)** 인 구간만 희망으로 취급 (1=하, 2=중) |
| `funding_type` | `student.funding_type`. 비었거나 알 수 없는 값이면 상한이 더 낮은 교비로 폴백 |
| `active_from` / `active_until` | 합격 공고의 근로 기간(`job_posting.period_start` / `period_end`) |
| `unavailable_dates` | 별도 필드 없이 종일 `UNAVAILABLE` 예외로 처리 — 전개 단계에서 그날 구간이 비워진다 |

DB에 아직 소스가 없어 도메인 기본값으로 두는 항목이 있고, **그만큼 해당 제약이 이 경로에서 동작하지 않는다**:

| 항목 | 영향 |
|---|---|
| `class_times` | 학생이 수업 시간을 뺀 가용시간을 제출하는 전제(SAINT 연동 전). 공휴일·교내 휴강일에 "원래 수업이라 못 냈던 시간"을 되살리는 HC-CLASS-3/4 경로는 동작하지 않는다 |
| `exams` | SC-EXAM-1(시험 직전 버퍼) 미적용 |
| `avoid_ranges` | SC-AVOID-1(회피 요청) 미적용 |
| `preferences` | 전원 도메인 기본값. `campus_days`가 비어 SC-COMMUTE-1은 미적용이고, 아침 근무 상한(SC-MORN-2/3)·식사 희망(SC-MEAL-*)은 개인화 없이 기본값으로 일괄 적용된다 |

기존 운영 엑셀에서의 이관: `tools/import_xlsx.py`가 정보서비스팀 워크북(개인 시트의 30분/행 병합 셀 그리드)에서 `date_schedule` 형식으로 자동 추출한다 (프로토타입·오프라인 실행용 경로). 이때 적용되는 해석 규칙:

- **상태값 해석**: `근무 가능` → available, `근무 희망` → available + preferred, `수업` → classes. **그 외 모든 상태(식사, 기타, 시험, 대청소, 빈칸)는 배정 불가**로 해석한다.
- **팀 운영 규칙 반영**: 개인 시트 공지의 "오전 8시 근무는 격일 이상으로 배정" 규칙에 따라, 임포트되는 모든 학생의 `max_consecutive_morning_days`를 **1**로 설정한다 (아래 표의 기본값 6은 도메인 기본값일 뿐, 실데이터 실행에서는 1이 적용됨). `wants_meal_break`도 false로 설정한다 — 식사 시간은 학생이 시트에 직접 마킹해 가용시간에서 이미 제외되기 때문.

개인 편의 옵션(`preferences`):

| 옵션 | 기본값 | 의미 |
|---|---|---|
| `no_morning_after_close` | true | 전날 마감(폐관 직전 슬롯) 근무 시 다음 날 아침 근무 제외 희망 |
| `max_consecutive_morning_days` | 6 | 아침 근무 최대 연속 일수 (0 = 아침 근무 불가능) |
| `max_morning_days_per_week` | 6 | 주당 아침 근무 최대 일수 (0 = 아침 근무 불가능) |
| `wants_meal_break` | true | 식사 시간 보장 희망 |
| `campus_days` | [] | (학기 중) 원래 학교에 오는 요일 — 통학 부담 고려. 빈 값이면 미적용 |

### 2.2 부서 정책 (`config/departments/*.json`)

부서 담당자가 입력하는 값으로, **코드에 하드코딩하지 않고** JSON으로 분리한다. MVP 값은 로욜라도서관 정보서비스팀 기준.

어떤 부서가 어떤 파일을 쓰는지는 DB(`department_policy.policy_file_key`)에서 읽고, 값이 없으면 기본 정책 파일로 폴백하며 경고 로그를 남긴다. **정책 내용 자체는 아직 JSON**이며, `department_policy` 테이블로의 이관은 후속 작업이다 (7장).

| 항목 | MVP 값 | 설명 |
|---|---|---|
| `slot_minutes` | 30 | 슬롯 길이 (담당자가 쪼갤 수 있음) |
| `staffing.min_per_slot` / `max_per_slot` | 1 / 2 | 시간대별 최소/최대 배정 인원 |
| `staffing.allow_understaffing_with_penalty` | true | 최소 인원 미달을 "해 없음" 대신 페널티+리포트로 처리 (4장) |
| `hour_limits.*` | 3.1 참고 | 주/월/2주 시간 상한 |
| `opening_hours.*` | 3.2 참고 | 기간·요일별 개관 시간, 공휴일 단축, 시험 주말 연장 |
| `preferred_staffing_bands` | 3.4 SC-STAFF | 시간대별 선호 인원 |
| `meal_windows`, `morning_end`, `exam_buffer_minutes` | — | Soft Constraint 파라미터 |
| `soft_weights` | 3.5 참고 | Soft Constraint 가중치 (0이면 해당 제약 비활성화) |

### 2.3 학사 캘린더 (`config/academic_calendar_{년도}.json`)

| 항목 | 설명 |
|---|---|
| `semesters` | 학기 구간 — 나머지 기간은 방학으로 판정 |
| `exam_periods` | 시험 기간 — 주말 연장 개관 계산에 사용 |
| `public_holidays` | 법정 공휴일 (선거일, 대체공휴일 포함). **매년 변동 — 한국천문연구원 특일 정보 OpenAPI 연동으로 갱신 예정** |
| `school_only_holidays` | 교내만 휴강인 날 (부활절 휴가 등) |
| `closures` | 도서관 폐관일 (하계 집중 휴무 등) |

## 3. 제약조건

### 3.1 Hard Constraint — 시간 상한 (HC-TIME)

| ID | 규칙 | 적용 대상 |
|---|---|---|
| HC-TIME-1 | 주당 근로 ≤ **14시간** | 교비 (학기/방학 동일) |
| HC-TIME-2 | 주당 근로 ≤ **20시간**(학기) / **40시간**(방학) | 국가 |
| HC-TIME-3 | 월별 근로 ≤ **46시간** (부서별 입력 가능) | 국가 |
| HC-TIME-4 | 부서 전체 2주 교비 근로 총합 ≤ **190시간** (부서별 입력 가능) | 교비 전원 합산 |

- "주"는 ISO 주(월-일) 기준. 한 주에 학기·방학이 섞이면 **보수적으로 더 낮은 상한** 적용
- HC-TIME-3은 스케줄링 기간 내 날짜만 집계. 같은 달의 기간 외 기근무 이월 차감은 DB 연동 후 확장
- HC-TIME-4는 스케줄링 시작일부터 14일 단위 창(window)으로 적용 — 스케줄링 기간을 2주 단위로 잡는 것을 권장

### 3.2 Hard Constraint — 개관 시간 (HC-OPEN)

개관 시간 밖 슬롯에는 배정 변수를 만들지 않는다. 날짜별 개관 시간은 아래 우선순위로 결정:

| ID | 우선순위 | 규칙 |
|---|---|---|
| HC-OPEN-1 | 1 | **폐관일**(`closures`, 하계 집중 휴무 등) → 배정 없음 |
| HC-OPEN-2 | 2 | **방학 중 공휴일** → 폐관 |
| HC-OPEN-3 | 3 | **학기 중 공휴일** → 단축 개관 (MVP: 09:00-17:00). 단, 원래 폐관 요일(일요일)에 겹치면 그대로 폐관 |
| HC-OPEN-4 | 4 | **학기 중 교내 휴강일**(부활절 등) → 공휴일과 동일하게 단축 개관 (근무 가능 규칙은 HC-CLASS-4가 별도 적용) |
| HC-OPEN-5 | 5 | **시험 기간 연장 주말** → 연장 개관 (MVP: 토·일 08:00-22:00) |
| HC-OPEN-6 | 6 | 그 외 → 기간(학기/방학)·요일별 기본 개관 시간 |

**시험 기간 연장 주말 판정** (요구사항의 5가지 케이스를 요일 규칙으로 일반화):

```
시험 시작 요일이 월/화 → 시험 "직전" 주말 연장
시험 시작 요일이 수/목/금 → 시험 기간 "사이에 낀" 주말(시작 후 첫 주말) 연장
```

### 3.3 Hard Constraint — 수업·가능 시간 (HC-CLASS)

| ID | 규칙 |
|---|---|
| HC-CLASS-1 | 근무 가능 시간(`available`)으로 체크하지 않은 슬롯에는 배정 불가 |
| HC-CLASS-2 | **수업 시간에는 절대 배정 불가** — 정규 학기·계절 학기·시험 기간 모두. 시험/실험으로 실제 수업이 없어도 기존 수업 시간은 근로 불가 |
| HC-CLASS-3 | **공휴일**: 수업이 없으므로 수업 시간표와 무관하게 배정 가능 (가능 시간 ∪ 원래 수업이라 못 냈던 시간) |
| HC-CLASS-4 | **교내 휴강일**(부활절 등): 교비는 HC-CLASS-3과 동일하게 배정 가능, **국가는 해당일 근로 자체가 불가능** |
| HC-CLASS-5 | `unavailable_dates`로 신고한 특정일에는 배정 불가 |
| HC-CLASS-6 | **활동 기간 밖 배정 불가** — `active_from` 이전, `active_until` 이후 날짜에는 배정 변수를 만들지 않는다 (중도 합류, 시즌별 근무 반영) |

### 3.4 Hard Constraint — 배정 인원 (HC-STAFF)

| ID | 규칙 |
|---|---|
| HC-STAFF-1 | 모든 개관 슬롯의 배정 인원 ≤ `max_per_slot` (MVP: 2명) |
| HC-STAFF-2 | 모든 개관 슬롯의 배정 인원 ≥ `min_per_slot` (MVP: 1명). 단, `allow_understaffing_with_penalty`가 true면 4장의 완화 규칙 적용 |

### 3.5 Soft Constraint

각 Soft Constraint는 위반량 변수를 만들고 `soft_weights`의 가중치를 곱해 목적함수에 더한다. **가중치가 클수록 우선 보호**되며, 0이면 비활성화된다. MVP 가중치는 정보서비스팀 기준.

| ID | 제약 | 위반량 정의 | MVP 가중치 |
|---|---|---|---|
| SC-UNDER-1 | 최소 인원 미달 (4장) | 슬롯별 부족 인원 수 | **1000** (사실상 Hard) |
| SC-STAFF-1 | 시간대별 선호 인원 — 근로 선생님 재실 시간대(학기 평일 09-12, 13-17시 등)는 2명 선호 | 슬롯별 (선호 인원 − 배정 인원) | 8 |
| SC-STAFF-2 | 선생님 부재 시간대(학기 평일 저녁, 방학 저녁·토요일)는 가능하면 2명 | 〃 | 4 |
| SC-PREF-1 | 희망 시간 우선 배정 | 희망하지 않은(가능만 한) 슬롯 배정 수 | 3 |
| SC-CONT-1 | 연속 근무 선호 — 조각 근무 최소화 | 학생-일자별 근무 블록 시작 횟수 | 4 |
| SC-MEAL-1 | (학기) 점심 12-13시 / 저녁 17-18시가 수업+근무로 전부 채워지면 위반. 시험 기간의 "수업X 시험X" 시간은 식사 가능으로 간주 | 학생-일자-시간대별 0/1 | 20 |
| SC-MEAL-2 | (방학) 6시간 이상 배정된 날 점심 시간대 미확보 | 〃 | 20 |
| SC-MORN-1 | 전날 마감 근무 후 다음 날 아침 근무 | 학생-일자별 0/1 | 15 |
| SC-MORN-2 | 주당 아침 근무 일수 초과 | 초과 일수 | 10 |
| SC-MORN-3 | 아침 근무 연속 일수 초과 | 연속 창(window)별 0/1 | 10 |
| SC-EXAM-1 | 시험 시작 전 버퍼(MVP: 3시간) 내 배정 | 해당 배정 슬롯 수 | 25 |
| SC-AVOID-1 | 회피 요청 시간대(축제 당일 저녁 등) 배정 | 해당 배정 슬롯 수 | 12 |
| SC-COMMUTE-1 | (학기) 원래 등교하지 않는 요일 배정 — 통학 부담 | 해당 근무 일수 | 5 |
| SC-FAIR-1 | 근무 시간 공평 배분 — 주간 목표 시간(= min(주간 상한, 그 주 본인 가용 슬롯)) 미달 시 페널티. 각자 가능한 만큼에 비례해 고르게 채워, 특정 학생에게 시간이 쏠리는 것을 방지 | 학생-주별 목표 미달 슬롯 수 | 6 |

- SC-MORN-*은 `max_*_morning_days = 0`(아침 근무 불가능) 선택 시 Soft가 아니라 **Hard로 승격**되어 아침 슬롯 배정이 금지된다
- "아침"의 경계는 정책 `morning_end`(MVP: 09:00) 이전 슬롯
- SC-PREF-1의 '희망'은 DB 경로에서 `available_time.preference == 3`(상)인 구간을 뜻한다 (2.1). 수합 데이터에 3이 하나도 없으면 모든 배정이 같은 페널티를 먹어 이 제약이 배정을 유도하지 못한다

### 3.6 목적함수

```
minimize  Σ ( weight[c] × violation[c] )   (c: 모든 Soft Constraint 위반 항)
```

풀이 후 제약별 페널티 합계(`penalty_breakdown`)를 결과에 포함해, **어떤 제약이 얼마나 희생됐는지** 담당자가 확인할 수 있게 한다.

**솔버 상태의 의미** (결과의 `status`):

| 상태 | 의미 | 처리 |
|---|---|---|
| `OPTIMAL` | 최적해 — 이보다 페널티가 낮은 배정은 존재하지 않음이 증명됨 | 정상 결과 |
| `FEASIBLE` | 시간 제한 내 찾은 최선의 해 (더 나은 해가 있을 수도 있음) | 정상 결과 — 긴 기간 풀이에서 일반적 |
| `INFEASIBLE` | Hard Constraint를 만족하는 해가 **없음이 증명됨** | API 409 |
| `UNKNOWN` | 시간 제한 내에 해를 찾지 못함 (해 없음이 증명된 것 아님) | API 504 — 기간 축소 또는 시간 제한 증가 후 재시도 |

**재현성(비결정성)**: 같은 페널티 총합을 갖는 동률 해가 여러 개면, CP-SAT은
멀티스레드 탐색 특성상 **실행마다 다른 시간표를 반환할 수 있다**. 즉 같은
입력으로 "생성"을 다시 눌러도 결과가 달라질 수 있다. 완전한 재현이 필요하면
`random_seed` 고정 + 단일 워커(`num_workers=1`)로 실행할 수 있으나 풀이가
느려진다. MVP는 재현성 대신, 동률 해를 **여러 개 열거해 담당자가 고르는**
방향을 택한다 (아래).

**동률 해 열거** (`solve_alternatives`, API `num_alternatives`):

1. 첫 해를 찾고 그 페널티 총합 V를 기록한다
2. 모델에 두 제약을 추가하며 반복 풀이한다:
   - **페널티 총합 ≤ V** — 이후 해는 첫 해와 동률이거나 더 나아야 함
   - **다양성 컷** — 이미 찾은 각 해와 슬롯 배정이 최소 `min_difference_slots`개
     (기본 4개) 달라야 함. 사소한 30분 스왑만 다른 대안이 나오는 것을 방지
3. 조건을 만족하는 해가 소진되거나(INFEASIBLE) 시간 제한에 걸리면 그때까지
   찾은 해들만 반환한다. `time_limit_seconds`는 **해 하나당** 제한이다

검증: 더미 데이터(8명, 2주)에서 3개 배정안이 페널티 13,500-13,512 범위로
나오고, 배정안 간 슬롯 차이는 200개 이상 — 실질적으로 다른 시간표가 열거됨.

## 4. 해가 없을 때 (Infeasible 처리)

학생들이 낸 가능 시간만으로 최소 인원을 채울 수 없는 상황은 실제로 자주 발생한다. 이때 "해 없음"으로 끝내면 담당자는 원인을 알 수 없다.

- `allow_understaffing_with_penalty = true`(기본값)면 HC-STAFF-2를 **슬롯별 부족 인원 변수 + 큰 페널티(SC-UNDER-1)** 로 완화한다
- 솔버는 항상 배정안을 내놓되, **최소 인원 미달 슬롯 목록**(날짜, 시간대, 부족 인원)을 결과에 포함한다
- 담당자는 이 리포트를 보고 가능 시간 추가 수합, 인원 충원, 개관 축소 등을 판단한다
- 시간 상한(HC-TIME-*)이나 최대 인원(HC-STAFF-1)은 완화하지 않는다 — 규정 위반 배정은 어떤 경우에도 출력되지 않음

## 5. 처리 흐름과 구현 대응

```
[API] POST /api/schedule/generate     routers/schedule.py (직원 전용, 409/504 구분)
   ↓
[어댑터] 수합 데이터(DB) · 정책·캘린더(config JSON) 로드 → 응답 JSON 변환
        scheduler/service.py + loader/availability.py (요일·예외 → 날짜별 전개)
   ↓
① 날짜별 개관 슬롯 그리드 구성        domain/calendar.py (OpeningHoursResolver)
   ↓
② 배정 변수 생성 (가능 슬롯에만)      engine/solver.py + domain/student.py (can_work)
   ↓
③ Hard Constraint 추가               constraints/hard.py
   ↓
④ Soft Constraint 페널티 등록        constraints/soft.py
   ↓
⑤ CP-SAT 풀이 (시간 제한: 해 하나당 기본 30초)   engine/solver.py
   · num_alternatives ≥ 2면 동률 해 열거 (solve_alternatives, 3.6 참조)
   ↓
[출력] 배정표 + 부족 슬롯(가능 후보 포함) + 페널티 이벤트(누구/언제/무엇)
       domain/result.py, reporting.py(콘솔), reporting_html.py(주차별 그리드·근거 표시)
   ↓
[저장] 초안 보존 — schedule_batch(status="draft") + work_schedule(날짜 단위)
       routers/schedule.py — 같은 부서·기간으로 재호출하면 기존 draft만 교체하고
       confirmed 배치는 건드리지 않는다
```

- 제약조건은 **클래스 하나 = 제약 하나**로 구현하며(`constraints/`), 새 제약은 클래스 추가 + 기본 목록 등록으로 확장한다
- 정책·캘린더 로딩은 `config/__init__.py`로 일원화 — 반환 타입(도메인 객체)을 유지한 채 내부만 DB 조회로 교체 가능

### 출력 (시간표 시각화·근무 시간 확인의 데이터 소스)

| 항목 | 용도 |
|---|---|
| 날짜별 · 슬롯별 배정 학생 목록 (희망 매치 여부 포함) | 주간 그리드 시각화, 개인별 시간표 표시 |
| 학생별 일/주/2주 근무 시간 집계, 희망 반영률 | 개인별 근무 시간 확인 |
| 부서 교비 주별·2주 총합, 국가 월별 총합 | HC-TIME-3/4 모니터링 |
| 최소 인원 미달 슬롯 목록 + **그 슬롯의 가능 후보** | 담당자 판단: 후보 없음 → 추가 수합, 후보 있음 → 수동 조정 검토 |
| Soft Constraint별 페널티 내역 + 위반 이벤트(누구/언제/무엇) | 배정 근거 설명, 시나리오 비교 |

HTML 리포트(`reporting_html.py`)는 위 정보를 담당자 관점으로 렌더링한 참고 구현이다:
슬롯 툴팁(가능 후보·근거), 빈 슬롯 2종 구분(가능자 없음=빨강 / 미배정=주황),
주차별 페널티 배지·상세, 학생별 수합 시간표 위 배정 오버레이 뷰.

## 7. 확장 계획

| API 노출 | **1차 완료** | `POST /api/schedule/generate`(직원 전용, 근거 포함 응답, 409/504 구분)와 가능시간 수합 API(`POST /api/availability`, 부서 수합 조회, 날짜 예외 등록/조회) 구현. 남은 것: 확정 근무표 조회 API, draft→confirm 확정 플로우 |
