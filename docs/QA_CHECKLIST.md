# QA 체크리스트

발표·데모 전에 손으로 눌러 확인하는 목록입니다. 자동 테스트가 덮지 못하는 것 —
**솔버 결과가 실제로 쓸 만한가**, **AI가 사람에게 쓸 만하게 느껴지는가** — 에 무게를 둡니다.

## 쓰는 법

- 배포 데모(http://3.34.82.68)에서 확인합니다. 계정은 [README](../README.md) 데모 표 참고.
- 통과는 체크만, **실패·애매한 것은 아래 '발견 기록'에 남깁니다.** 애매한 것을 그냥
  넘기면 다음 사람이 같은 것을 다시 의심합니다.
- 수치를 적는 칸은 **실제 화면에 뜬 값**을 적습니다. 기억이나 추정으로 적지 않습니다.

## 1. 근무표 생성 — 솔버

이 절의 핵심은 **"최적"이라는 말이 두 가지를 뜻한다**는 점입니다.

- **1-A는 기계가 스스로 증명한 것**입니다. `OPTIMAL`은 *우리가 준 목적함수 기준으로*
  더 나은 해가 없음을 증명했다는 뜻이지, 사람이 보기에 최선이라는 뜻이 아닙니다.
- **1-B는 사람만 판단할 수 있는 것**입니다. 목적함수가 현실을 잘 담고 있는지는
  솔버가 답해주지 않습니다.

둘 다 봐야 합니다. 1-A만 보면 "OPTIMAL이니까 괜찮겠지"로 넘어가게 됩니다.

### 1-A. 기계적 확인 (화면 값만 보면 됨)

근무표 편성 → 부서 근무표 생성 시작 → 상단 요약 카드에서 확인합니다.

- [ ] **풀이 상태 = `최적해(OPTIMAL)`** — `FEASIBLE`이면 시간 안에 최적임을 증명하지
      못한 것이라 더 나은 배정이 있을 수 있습니다. 값: `________`
- [ ] **미충원 = 0칸** — 0이 아니면 최소 인원을 못 채운 슬롯이 있습니다. 값: `____칸`
- [ ] **풀이 시간** 기록 (참고: 로컬 2주 기준 2\~3초). 값: `____초`
- [ ] **배정 건수**가 기간·인원에 비해 터무니없지 않은지. 값: `____건`
- [ ] 하단 **'최소 인원 미달 슬롯'** 목록이 비어 있는지

부서를 바꿔 최소 2개 부서에서 확인합니다 (`STF001` 정보서비스팀 / `STF011`
아트&테크놀로지학과-test는 수업 조교 편성이라 성격이 다릅니다).

- [ ] 정보서비스팀 — 상태: `________` / 미충원: `____`
- [ ] 아트&테크놀로지학과-test — 상태: `________` / 미충원: `____`
- [ ] 교육대학원 행정팀-test — 상태: `________` / 미충원: `____`

### 1-B. 사람이 판단할 것

**Soft Constraint 희생량** 표를 봅니다(낮을수록 좋음). 절대값보다 **어디에 몰려 있는지**가
중요합니다.

- [ ] 희생이 **한 항목에만 극단적으로 몰려 있지 않은지**. 몰려 있다면 그 항목이 정말
      덜 중요한 게 맞는지 판단이 필요합니다. 기록:
      `주간 목표 시간 미달 ____ / 희망 외 시간 배정 ____ / 식사 시간 미확보 ____ /`
      `선호 인원 미충족 ____ / 근무 블록 분절 ____`
- [ ] **개인별 근무 시간 표**를 보고 특정 학생에게 시간이 쏠리지 않았는지. 최대·최소
      학생의 차이: `____시간`
- [ ] 상한(교비 14h)에 **딱 붙은 학생이 몇 명**인지 — 전원이 상한에 붙어 있으면
      인원이 부족하다는 신호입니다. 값: `____명`
- [ ] 눈으로 봤을 때 **"이건 사람이면 이렇게 안 짠다" 싶은 배정**이 있는지. 있으면
      구체적으로 기록 (예: 하루에 1시간짜리 근무만 뚝 떨어져 있음)

### 1-C. 제약이 실제로 지켜지는가

`SCHEDULER_SPEC.md`의 hard 제약 중 화면에서 확인 가능한 것들입니다.

- [ ] **HC-CLASS-2** — 학생 수업 시간에 배정된 근무가 없는지. 학생 계정(`20220042`)으로
      근무 시간표를 열어 수업 시간과 겹치는 칸이 없는지 봅니다
- [ ] **HC-OPEN-1\~6** — 개관 시간 밖·휴관일에 배정이 없는지. 근무표에서 '근무 없음
      (개관 시간 밖)' 칸에 사람이 들어가 있지 않은지
- [ ] **HC-TIME-1** — 교비 학생 주당 14시간 초과가 없는지 (개인별 집계 표)
- [ ] **HC-CLASS-1** — 학생이 체크하지 않은 시간대에 배정되지 않았는지 (수합된 근무
      시간표 탭과 대조)

### 1-D. 안정성

- [ ] **같은 조건으로 다시 생성**했을 때 결과가 크게 달라지지 않는지. 배정 건수·희생량
      합계가 비슷한 수준인지 (완전히 같을 필요는 없습니다)
- [ ] 기간을 **3주·4주**로 늘려도 생성되는지, 풀이 시간이 감당 가능한지. 값: `____초`
- [ ] **한 학기 고정(2주 패턴 반복)** 확정이 되는지

## 2. AI 기능 — 잘 도는가 + 쓸 만하게 느껴지는가

기능이 도는 것과 **쓸 만하게 느껴지는 것은 다릅니다.** 각 항목에 동작(체크)과
체감(기록)을 나눠 뒀습니다.

체감 판단에 쓸 기준선(개발 중 실측):

| | 평균 | p90 | 최대 |
|---|---|---|---|
| AI 검토 (`eval_review.py`, 2026-08-30) | 6.5초 | 11.1초 | 19.8초 |
| 챗봇 한 턴 (`eval_chat.py`, 2026-08-31) | 8.7초 | — | 22.6초 |

**10초를 넘으면 기다린다는 느낌이 듭니다.** 20초를 넘으면 기록해 주세요.

### 2-A. AI 검토 (근무표 편성 → AI 검토 실행)

- [ ] 검토가 **실패 없이 끝나는지** (에러·타임아웃 없이)
- [ ] 소요 시간: `____초` — 10초 넘었으면 기록
- [ ] 지적된 내용이 **부서 운영 규칙과 실제로 관련 있는지**. 엉뚱한 지적이 있으면 기록
- [ ] **근거(evidence)가 붙어 있는지** — "누가·언제"가 특정되지 않은 지적은 확인이 불가능합니다
- [ ] 지적의 **심각도가 구분되는지**. 알려진 문제: 지금까지 실측에서 findings가 전부
      `critical`로 나와 담당자가 무엇부터 볼지 고를 수 없었습니다(#195).
      이번에도 그런지 확인: 위반 `___건` / 우려 `___건` / 참고 `___건`
- [ ] **되묻기**가 뜨는 케이스가 있는지, 답변하면 반영되는지
- [ ] 규칙을 **일부러 어긴 근무표**(칸 편집으로 상한 초과 등)를 만들었을 때 잡아내는지

> 체감 한 줄 기록: 담당자 입장에서 이 검토 결과를 보고 **실제로 근무표를 고칠
> 마음이 드는가?** 아니라면 왜인지.

### 2-B. 시간표 검토 챗봇 (우측 하단)

- [ ] **조회** — "조수현 이번 주 근무 언제야?" 같은 질문에 **실제 데이터로** 답하는지
- [ ] **없는 것을 지어내지 않는지** — 근무가 없는 요일을 물었을 때 "없다"고 답하는지.
      과거에 없는 근무를 "삭제했다"고 답한 사고가 있었습니다(#213)
- [ ] **다건 수정** — "수요일 ○○ 근무 다 빼줘"가 **전부** 반영되는지. 5건 이상에서
      앞부분만 지워지고 멈추지 않는지(#222). 대상 `___건` → 반영 `___건`
- [ ] **되묻기** — 대상이 모호하면 바로 지우지 않고 확인하는지
- [ ] **되돌리기** — 수정 후 되돌리면 원래대로 **전부** 복구되는지
- [ ] **재생성 후 되돌리기** — 수정 → "식사시간 더 챙겨줘"(재생성) 후, 앞 수정 턴에
      배지가 `재생성으로 사라짐`으로 바뀌고 되돌리기 버튼이 **사라졌는지**. 버튼이
      남아 있으면 회귀 ([#269](https://github.com/sg-beaver/stream/issues/269))
- [ ] **재생성 후 재조정** — 위 상태에서 가중치를 한 번 더 조정할 때 "수동 수정 N건이
      사라집니다" 확인을 **다시 묻지 않는지**. 다시 물으면 회귀
      ([#268](https://github.com/sg-beaver/stream/issues/268))
- [ ] **잘려 나간 수정** — 한 번에 많이 시켜 중간에 끊겼을 때 배지가 `변경 반영됨`이
      아니라 `일부 실패`·`중간에 멈춤` 중 하나인지. `변경 반영됨`이면 회귀
      ([#267](https://github.com/sg-beaver/stream/issues/267))
- [ ] **근무 불가 조건** — "○○ 학생 수요일 근무 빼줘"의 작업 내역이 한국어
      (`근무 불가 조건 추가`)로 뜨는지. `add_constraint`로 뜨면 회귀
      ([#270](https://github.com/sg-beaver/stream/issues/270))
- [ ] 한 턴 소요 시간: `____초`
- [ ] 화면의 "변경 N건" 숫자가 실제 바뀐 건수와 맞는지

> 체감 한 줄 기록: **말로 고치는 게 손으로 고치는 것보다 빠른가?** 아니라면 어느
> 지점에서 느려지는지.

### 2-C. 대타 AI 적합성 검사 (대타 승인 화면)

- [ ] 승인 화면에 **검사 결과가 표시**되는지 (#207)
- [ ] 가능 시간·주간 상한 등 **판단 근거가 보이는지**
- [ ] 명백히 부적합한 후보(가능 시간 아님)를 실제로 걸러내는지
- [ ] 소요 시간: `____초`

### 2-D. 공통 — 신뢰와 통제

- [ ] **확정은 항상 사람이** 하는지 — AI가 자동으로 확정·삭제하는 경로가 없는지
- [ ] AI가 실패해도(키 없음·오류) **화면이 깨지지 않고** 근무표 자체는 보이는지
- [ ] 학생 이름·학번이 **AI 응답에 그대로 노출되어도 되는 맥락인지** (전송 시에는
      비식별화되지만 화면 표시는 별개입니다)

## 3. 이번 스프린트 회귀 확인

최근 고친 것들이라 데모 전에 한 번씩 눌러봐야 합니다.

- [ ] **칸 하나만 빼기** (#214) — 근무표 편성 → 배정 편집 → 연속 근무(예: 09:00\~22:00)
      중 한 칸만 클릭해 사람을 뺐을 때, **그 칸만** 없어지는지. 전체가 지워지면 회귀
- [ ] **확정본과 겹치는 기간 편집 저장** (#227) — 이미 확정된 기간과 겹치는 draft에서
      위 편집을 **저장**했을 때 400 오류 없이 반영되는지
- [ ] **재확정 후 승인된 대타** (#178) — 확정 → 대타 승인 → 겹치는 기간 재확정 후
      대타가 유지되는지. 유지 불가한 경우 확정 화면에 **"승인된 대타 N건이
      해제되었습니다"** 경고가 뜨고, 양쪽 학생 요청 기록이 `해제됨`으로 바뀌는지
- [ ] **대시보드 대타 링크 문구** (#74) — '대타 승인'으로 통일되어 있는지
- [ ] **서강대 폰트** (#76) — 크롬에서 폰트가 정상 로드되는지
- [ ] **대타 승인 표 버튼** (#76) — 좁은 화면에서 두 줄로 접히지 않는지
